## 1. Defect yang SUDAH DIPERBAIKI

### 1.1 `sitemap.xml` — XML tidak valid (P1,-blocking untuk Search Console)

Sesi rebrand sebelumnya menghapus 10 entri `<url>` untuk `punakawan/`, tetapi penanganannya merusak
struktur XML:

- Tag pembuka `<url>` pada entri pertama (baris 4) ikut terhapus → menjadi baris kosong
- Penutup `</urlset>` di akhir file terhapus → file **tidak valid XML sama sekali**

Dampak: `sitemap.xml` gagal di-parse Google Search Console. Selain itu masih ada 2 URL dengan trailing
slash tidak konsisten (`/primbon/` vs pola clean URL lain).

**Perbaikan:** tag `<url>` pertama dipulihkan, `</urlset>` ditambahkan, file divalidasi dengan parser XML.

```
Validasi:  XML VALID. url count = 6
  https://baiwor.my.id/
  https://baiwor.my.id/tentang
  https://baiwor.my.id/layanan
  https://baiwor.my.id/sinau
  https://baiwor.my.id/kontak
  https://baiwor.my.id/primbon/
```

### 1.2 `primbon/index.html` — tag `</div>` yatim (P2)

Blok kutipan (`.pb-quote`) dihapus, tetapi tag penutup `<div>`-nya tertinggal. Akibatnya `<div class="card">`
pada bagian "Tentang Kitab" tertutup terlalu awal dan struktur DOM bergeser.

```
Sebelum:  <div class="pb-quote">...</div>   ← pembuka dihapus, penutup tertinggal
Sesudah:  </p>
          </div>     ← yatim, dihapus
          </div>
```

**Perbaikan:** tag yatim dihapus. Semua file HTML kini seimbang (open == close untuk `div`, `span`, `a`,
`section`, `p`).

## 3. Temuan Fungsional — Chat live sedang MATI

Terverifikasi terhadap endpoint produksi:

```
POST https://baiwor.my.id/chat.php
→ {"error":{"message":"model 'qwen3:8b' not found","type":"not_found_error","code":null}}

POST https://chat.baiwor.my.id/chat.php
→ {"error":{"message":"model 'qwen3:8b' not found","type":"not_found_error","code":null}}
```

### 3.1 Dual failure

**Tier-1 (Gemini)** — mati karena kunci di-blokir Google (lihat 2.1).

**Tier-2 (fallback lokal VPS)** — mati karena **tidak ada model Ollama yang terpasang**:

```
$ ollama list
NAME    ID    SIZE    MODIFIED
                                ← kosong

$ curl -s http://127.0.0.1:12345/api/tags
{"models":[]}

$ curl -s http://127.0.0.1:12345/v1/models
{"object":"list","data":null}

$ du -sh /home/wijang/.ollama/models
12K     /home/wijang/.ollama/models      ← hanya 12K, hampir kosong
```

Ollama **prosesnya hidup** (`ollama serve`, PID 3182381, `OLLAMA_HOST=127.0.0.1:12345`, listening di
127.0.0.1:12345), tapi tidak ada satu pun model yang di-pull. Ketiga model fallback yang tertulis di
`chat.php` (`gemma4:31b-cloud`, `gpt-oss:20b-cloud`, `qwen3:8b`) tidak ada — error yang muncul adalah
model terakhir karena loop fallback menimpa `$error` tanpa Exit.

**Perbaikan yang dibutuhkan (server):**
```bash
ssh agentic "ollama pull gemma4:31b-cloud"   # atau model lain yang desired
```
Lalu verifikasi `ollama list` terisi dan `curl http://127.0.0.1:12345/api/tags` mengembalikan model.

**Bug tambahan di `chat.php` (P2):** loop fallback tidak menambahkan `break` saat gagal, sehingga
`$error`/`$httpCode` tertimpa iterasi terakhir dan pesan error yang muncul ke pengguna tidak
representatif. Kode juga tidak membedakan kondisi "tidak ada model" vs "server mati". Perlu
diperbaiki agar pesan error jujur dan mudah didiagnosis.

## 4. Catatan Optimasi (non-blocking)

### 4.1 `seo-local.html` — duplikat meta robots yang saling bertentangan
```
L1:  <meta name="robots" content="noindex, nofollow">
L39: <meta name="robots" content="index, follow, max-snippet:-1, max-image-preview:large">
```
Dua tag `<meta name="robots">` dalam satu dokumen. Crawler umumnya memakai yang pertama → baris 39
jadi tidak berpengaruh. Selain itu file ini **bukan halaman HTML utuh** (tanpa `<html>`, `<head>`,
`<title>`) — ia fragmen include, tapi bernama `.html` dan berada di root. Perlu dipastikan tidak
ter-deploy sebagai halaman mandiri, atau diubah ekstensinya (mis. `.inc`).

### 4.2 `token.html` — stub redirect tanpa meta description
Sudah benar: `noindex, follow` + canonical ke `/sinau` + `meta refresh` + fallback `<noscript>`.
Hanya `meta description` yang tidak ada — tidak berpengaruh karena halaman `noindex`.

### 4.3 Aset berat belum dioptimalkan

| File | Ukuran | Catatan |
|---|---|---|
| `baiwor_gunungan_original.png` | 6,3 MB | **Tidak terpakai** di HTML mana pun — kandidat dihapus |
| `baiwor_welcome.mp4` | 5,4 MB | dipakai di hero `index.html`, perlu `<source>` WebM + poster |
| `bAIwor_default.png` | 2,4 MB | tidak direferensikan |
| `banner_baiwor.png` | 2,4 MB | tidak direferensikan |
| `bAIwor_maskot.png` | 2,3 MB | tidak direferensikan (duplikat `maskot_baiwor.png`) |
| `bAIwor_pp.png` | 1,8 MB | dipakai sebagai logo **dan** `og:image` — og:image idealnya < 1 MB |
| `chat/bAIwor_pp.png` | 1,8 MB | duplikat dari root |

Total repo tracked: **28 MB**. Disarankan konversi ke WebP + `loading="lazy"` untuk gambar non-fold,
dan linkage `preload` untuk `bAIwor_pp.png` (dipakai 6x sebagai logo).

`kitab-asli.pdf` (31 MB) **tidak** ter-track git — sudah benar diabaikan oleh `.gitignore`. ✅

### 4.4 `baiwor-chat.php` — CORS wildcard + variabel `$hasSystem` tak terpakai

File ini berbeda dari `chat.php`/`chat/chat.php` (endpoint berbeda: ia memanggil model `minimax-m3:cloud`
langsung ke `localhost:12345`, bukan Gemini-first). Dua catatan:

- `header('Access-Control-Allow-Origin: *')` — wildcard, bertentangan dengan model CORS ketat di
  `chat.php` dan DEPLOY.md yang menyebut "CORS Terbatas: hanya origin resmi". Perlu konfirmasi file ini
  memang endpoint produksi yang aktif; jika ya, CORS harus diperketat.
- `$hasSystem` dihitung tapi tidak dipakai untuk keputusan logika — hanya flag "sudah ada system message",
  sehingga pesan sistem server bisa ditimpa klien (ironisnya `chat.php` justru stripping-nya).

**Catatan:** `go/` tidak ter-track git ✅ dan tidak boleh di-deploy (sesuai DEPLOY.md).
